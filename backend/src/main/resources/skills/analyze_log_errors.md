# analyze_log_errors —— 日志错误分析工具使用指南

## 何时使用
- 用户要求「分析/排查/看一下日志错误」「最近有没有报错」「线上出了什么异常」时。
- 仅分析服务端配置的日志目录（app.tools.builtin.log-dir）内的常规日志文件，不读取目录之外的任何路径；不接受文件路径参数，只接受可选的文件名。

## 调用前如何与用户确认
1. **时间窗 minutes（必填，1-1440 分钟）**：用户说「最近/刚才/今天」但未给范围时，先按建议默认 30 分钟调用，并在汇报时说明窗口；用户明确给了范围（如「最近 2 小时」）则换算为分钟（120）。
2. **fileName（可选）**：用户点名某个日志文件时传纯文件名（如 `application.log`），不要传路径；含 `/`、`..` 的值非法。
3. **topN（可选，1-50，默认 10）**：异常分组数量；用户要求「全部/详细」时可给 20-50。

## 参数
- `minutes`（整数，必填）：回溯时间窗（分钟）。只统计时间戳落在 `[现在-minutes, 现在]` 内的日志条目。
- `fileName`（字符串，可选）：仅分析日志目录内该文件；必须是 `^[A-Za-z0-9._-]+$` 的纯文件名。
- `topN`（整数，可选，默认 10）：异常分组返回前 N 个高频组。

## 返回结果如何解读
结果是一段 Markdown，包含：
- **扫描目录 / 时间窗**：实际扫描的绝对目录与窗口起止时间（北京时间）。
- **扫描文件**：每个命中文件及其窗口内命中行数；「跳过 mtime 过期 M 个」表示这些文件最后修改时间早于窗口起点，整文件未读取（快路径）。
- **级别计数**：`ERROR=` 窗口内 ERROR 行数；`WARN=` WARN 行数；`含异常堆栈=` 条目中出现 Exception/Throwable/堆栈帧的条目数。
- **无法解析时间戳的行**：不符合 Spring Boot 默认日志格式的条目数，未计入窗口统计（可能是第三方组件输出或多行内容）。
- **truncated**：`true` 表示触发了扫描上限（文件数 200 / 单文件 50MB / 总行数 200000），统计不完整——应在汇报中明确告知用户「日志量过大，结果已截断，建议缩小时间窗重试」。
- **异常分组 Top N**：每组含归一化后的异常类名与模式（数字、hex、UUID 已归一，同根因合并计数）、出现次数、首次/末次出现时间、代表性堆栈片段（≤15 行）。

## 向用户汇报的写法
1. **先结论后细节**：第一句话给出「窗口内共 N 条 ERROR、M 条 WARN，涉及 K 类异常」，再指出最高频的 1-3 个异常。
2. 对每个高频异常：异常类名 + 次数 + 首次/末次时间 + 堆栈中第一个**业务代码帧**（`com.dj.ai...` 开头的帧）所指位置。
3. 给出可执行建议：如「NullPointerException 集中在 XxxService:42，疑似空入参，建议检查上游调用」；信息不足时明确说需要进一步排查的方向，不要编造原因。
4. ERROR=0 时明确告知「窗口内无 ERROR 级别日志」，并顺带说明 WARN 数量。
5. `truncated=true` 或「日志目录不存在/为空」时，如实说明，不要虚构分析结果。

## 边界与安全
- 只扫描配置目录内的常规文件，不递归子目录，不跟随符号链接。
- 结果中的密钥（ark- key、Authorization、token 等）已脱敏为 `***REDACTED***`；如仍看到疑似密钥，不要复述，直接提示用户。
- 工具是只读分析：不修改、不删除任何文件，不执行任何命令。
