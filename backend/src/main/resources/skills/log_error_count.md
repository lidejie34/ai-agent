# log_error_count —— 日志错误计数脚本工具使用指南

## 能力说明
- 这是一个 **SCRIPT 类示例工具**（白名单脚本 `log_error_count.sh`），默认在管理端**禁用**，需管理员人工审计脚本内容后显式启用。
- 脚本只读：统计日志目录（执行器注入的 `LOG_DIR`）下 `*.log` 文件中包含 ` ERROR ` / ` WARN ` 的行数总和，不写文件、不联网。

## 何时使用
- 用户只需要一个粗略的错误数量量级（「最近大概有多少 ERROR」），且管理员已启用该工具时。
- 需要详细异常分类与堆栈时改用 `analyze_log_errors`（纯 JDK 内置分析，信息更全）。

## 参数
- `minutes`（整数，必填，1-1440）：回溯时间窗（分钟）。当前示例脚本按全量文件计数，minutes 作为语义参数透传，结果解读时以脚本输出为准。

## 返回结果如何解读
- `log_dir=<目录> minutes=<N>`：实际扫描的目录与参数。
- `ERROR_lines=<N>` / `WARN_lines=<N>`：所有 `.log` 文件中 ERROR/WARN 行数合计（grep -c 按文件计数后 awk 求和）。
- 计数为 0 且目录下无 `.log` 文件时，输出仍为 0——不代表服务正常，只代表没有匹配文件。

## 安全约定
- 脚本在白名单目录内以 `/bin/sh <脚本文件>` 方式执行，模型参数仅作为独立 argv 传入（`--minutes <值>`），shell 元字符无语义。
- 执行环境变量经净化（不继承 ARK_API_KEY/DB 口令），工作目录锁定为脚本目录。
- 新增/修改脚本必须由管理员人工审计后再启用；生产环境脚本目录应只读挂载。
